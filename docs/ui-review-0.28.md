## 评审方法

不使用主观描述，全部基于可复现的测量：

1. **实际渲染** — Godot 4.7.2 真实运行，1600×980，非模拟稿。
2. **像素统计** — 采样色分布、明度直方图，判断层级与视觉噪声。
3. **对比度计算** — WCAG 相对亮度公式，逐对验证 `system.md` 声明的语义 token。
4. **令牌采用率** — 统计代码中语义 token 与硬编码值的比例。

## 结论二：真正的问题是令牌采用率，不是配色

这是本次评审最重要的一项，也是 Interface Design 「Use What Exists / 绑定语义 token」的直接违反。

`ui_theme.gd` 定义了 17 个语义 token（CANVAS / SURFACE / SURFACE_ALT / INK / MUTED / ACCENT / BORDER / BORDER_STRONG / SUCCESS / WARNING / DANGER / BLUE 等），但全项目只有 `story_app.gd` 引用了 **2 处**（第 107 行 `Ui.CANVAS`、第 127 行 `Ui.ACCENT`）。

其余 UI 代码直接写死颜色。UI 层（排除地图渲染）的硬编码分布：

| 文件 | 硬编码色数 | 性质 |
|---|---|---|
| `story_app.gd` | 10 | 6 处是 UI 色，应走 token |
| `menu_art.gd` | 9 | 装饰绘制，可接受 |
| `tutorial_spotlight.gd` | 6 | 教学浮层，自成一套浅色配色 |
| `schematic_view.gd` | 6 | 示意图绘制 |
| `history_growth.gd` | 3 | 绘制 |
| `challenge_hub.gd` | 2 | 1 处是 `#111923` = CANVAS |
| `history_player.gd` | 2 | 2 处都是 `#111923` = CANVAS |
| `schematic_panel.gd` | 1 | `#111923` = CANVAS |

`map_view.gd`（62 处）与 `map_style.gd`（16 处）属于地图渲染，`system.md` 第 11 行已明确「地图独立使用 map_style.gd」，不计入漂移。

**重复字面量证据**（同一颜色在多处重复书写）：

- `#111923`（= CANVAS）在 UI 层重复 **6 次**，跨 5 个文件
- `#223745` 重复 7 次
- `#ffffff` 重复 10 次
- `#24745E` 重复 5 次

这正是 Interface Design 所说的「同一个值喷洒各处 = 缺 token 或组件，不是设计」。

## 结论三：教学浮层是唯一实质性视觉不一致

`tutorial_spotlight.gd` 用了一套**浅色**配色：面板 `#FFFEFA`、边线 `#B7CEC2`、文字 `#24332F`、强调 `#24745E`。而全应用是深色地图 + 深色工具面板。

这在逻辑上有其合理性（浮层需要从深色地图上跳出来），但它绕过了主题系统，且没有登记在 `system.md` 中——`system.md` 只描述了深色一套。结果是：**同一产品存在两套未记录的视觉语言**。

## 结论四：字号规格未落实为约束

`system.md` 声明「正文18px、辅助≥15px、分组20px、对象标题24px、菜单标题44px」，但代码中的字号字面量是 12 / 15 / 16 / 18 / 24 / 28，且**没有 20 和 44**。

- `story_app.gd:187` 用了 **12px**，低于 `system.md` 声明的「辅助≥15px」下限
- `tutorial_spotlight.gd:69` 用 `maxi(16, font_size)`，16px 同样低于 15px 下限的声明意图
- 声明的 20px（分组）与 44px（菜单标题）在代码中不存在

说明 `system.md` 的字号表是**意图**，不是**已实施的约束**。文档与实现已经脱节。

## 结论五：圆角规格基本符合

`system.md` 声明「6—8px 圆角」。`ui_theme.gd` 实测：8px（14 次）、6px（1 次）为 UI 主用；10px（3 次）用于弹窗、12px（2 次）用于窗口、2px（9 次）用于滑块轨道与光标。弹窗用 10px 略超声明范围，属于合理分级（小控件→卡片→弹窗），建议把这条分级写进 `system.md`，而不是改代码。
