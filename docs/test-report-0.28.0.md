# 0.28 测试报告

测试日期：2026-11-09
测试对象：metro-atlas-desktop 0.28.0（深圳单城 + 提案玩法）
测试方法：白盒代码审查 + 黑盒真实窗口驱动 + 变异测试验证

## 结论

发现并修复 **7 个缺陷**，其中 **2 个是阻断级**（提案面板完全不显示、继续游戏按钮对所有人禁用）。
修复后 30 个 GD 测试全部通过，完整门禁通过。

## 缺陷清单

### 阻断级

**1. 提案面板完全无法显示**（`story_app.gd` `_left()`）

左侧面板只有 `intro` 和 `outcome` 两个分支，没有 `proposal`。玩家进入任何规划章，
点「先做本期提案」后，页面变成空白，既看不到站序列表，也没有提交/跳过按钮，**无法继续游戏**。

发现方式：黑盒驱动真实控件，断言「本期提案」标签可见，结果 false。

修复：新增 `elif stage==ProposalSession.STAGE_PROPOSAL` 分支渲染 `_proposal_panel`。

**2. 「继续城市故事」对所有玩家禁用**（`story_app.gd` `_last_game_is_published()`）

`last_game.json` 只是索引，内容为 `{"gameId":..., "schemaVersion":25}`，**没有 cityId**。
原实现直接读这个文件找 cityId，永远找不到，返回 false，按钮永久禁用。
即使是深圳自己的存档也打不开。

发现方式：程序化检查存档文件结构，发现顶层只有两个键。

修复：改为顺着索引读 `games/<gameId>/current.json`，那里才有 `cityId`。

### 严重级

**3. 换乘命中率永远为 0**（`proposal_scoring.gd` `compare_order`）

`requiredTransfers` 的 `name` 是站名（如「老街」），但 `served` 存的是站 ID。
用站名去站 ID 列表里查，**永远查不到**。玩家全选 18 站（含全部 7 个换乘站），
显示「换乘命中 0 / 7」，满分只能拿 90。

发现方式：用真实章节数据驱动评分，对比期望值与实际值。

修复：参数改为 `transfer_ids`，UI 层把站名解析成候选站 ID 再传入。

**4. 倒序选站仍能及格**（`proposal_scoring.gd`）

`order_ratio = longest / total`，倒序时 `longest=1`，n 越大惩罚越小。
2 站线路全选倒序得 85 分，评级「贴合公开方案」——**把顺序完全搞反反而拿高分**。

发现方式：构造 2/3/4/5/10/20 站线路的倒序用例，观察分数随站数变化。

修复：改为 `(longest - 1) / (total - 1)`，完全倒序归零；同时把权重从
覆盖 60 / 顺序 30 / 换乘 10 调整为 **35 / 45 / 20**，让顺序比覆盖更重要。
修复后倒序统一 55 分「偏离较多」。

**5. 提案阶段可以建设**（`story_app.gd` `_refresh()`）

车站/铺轨按钮只在 `stage=="build"` 时禁用，提案阶段没有覆盖。
玩家可以在还没提交提案时直接建设，等于**用行动回答了本该先回答的问题**。

发现方式：黑盒检查 `station_button.disabled`，结果 false。

修复：加入 `drawing_proposal` 条件，三个工具按钮全部禁用并给出提示。

### 一般级

**6. `proposals` 损坏时提交崩溃**（`story_session.gd` `submit_proposal`）

`var proposals: Dictionary = world.storyState.get("proposals", {})` —— 用 `Dictionary`
类型标注接收任意值，当存档里是字符串时**赋值瞬间就抛错**，后面的 `is Dictionary` 检查
根本执行不到。旧存档或手工改过的存档会直接崩。

发现方式：构造损坏数据测试。

修复：先用 `Variant` 接收，再判断类型。

**7. 提案阶段提示文本错误**（`story_app.gd` `_instruction()`）

提案阶段显示「点击选择；拖动空白处平移」，但此时地图上没有任何可点的东西。

修复：新增提案阶段分支，提示「在左侧按顺序点选公开站序，选够两站后提交；也可以直接跳过」。

## 测试盲区（已补强）

原有测试全部通过，但**一个都没能捕获上述缺陷**。原因：

| 缺陷 | 为什么原测试没抓到 |
|---|---|
| 面板不显示 | `proposal_session_checks` 只测 `Story` 层状态机，不测 UI 渲染 |
| 继续按钮禁用 | `published_only_checks` 只测 `WorldData.is_published`，不测存档结构 |
| 换乘永远 0 | `proposal_order_checks` 传的是 id，恰好绕过了真实数据里的站名 |
| 倒序及格 | 原断言只要求 `orderRatio < 0.5`，旧值 0.2 也能通过 |
| 提案阶段可建设 | 没有任何测试检查工具按钮状态 |
| 损坏数据崩溃 | 没有损坏数据用例 |
| 提示文本 | 没有断言提示内容 |

补强措施：
- `proposal_order_checks` 21 → 28 项，新增倒序必须零分、必须不及格、2 站线路用例
- 新增 `proposal_ui_checks`（45 项）：黑盒驱动真实控件
- 新增 `proposal_panel_checks`（22 项）：断言面板真的渲染出来
- 新增 `city_boundary_checks`（9 项）：存档隔离，含「不修改不删除他人存档」
- 新增 `hub_city_checks`（11 项）：挑战页与存档页不出现其他城市
- 新增 `proposal_compat_checks`（8 项）：损坏数据不崩溃
- 新增 `proposal_resume_checks`（10 项）：提案阶段跨存档恢复

## 变异测试

为确认新测试真的有效，逐个把修复改回原样，验证测试会失败：

| 变异 | 结果 |
|---|---|
| `order_ratio` 改回 `longest / total` | **5 项失败** ✓ |
| 移除 `_load_result` 城市守卫 | **2 项失败** ✓ |
| 移除 `proposal` 面板分支 | **12 项失败** ✓ |

- 数据完整性：9 张决策卡全部有官方来源，5 张规划卡 chapterId 全部有效，
  143 个规划站坐标零缺失

### 黑盒

- 主菜单：无其他城市入口，副标题为单城文案
- 开始新故事：城市下拉仅深圳一项

- 单站提案：被拒绝并说明「至少选择 2 座车站」
- 存档隔离：其他城市存档不列出、载入被拒、文件未被修改或删除
- 挑战页：城市下拉仅深圳，每日题不服务其他城市
