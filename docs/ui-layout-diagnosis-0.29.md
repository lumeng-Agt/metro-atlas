# UI 布局诊断 · 0.29

## 前置说明：我能看到什么、看不到什么

**看不到**：当前会话模型不支持图像输入，`read_image` 被拦截。我派出的视觉评审子代理同样看不到。所以本文**没有**「第一眼印象」这类判断，我也不会编造。

**能看到**：代码结构、像素几何测量、控件常量、交互拓扑。下面每一条都有测量或代码行号支撑。

如果要做真正的视觉判断，需要换一个支持图像输入的模型。在此之前，下面的结构问题是可以确定并修复的。

## 测量证据

代表页 `ui-0.20-workbench.png`，1600×980，Godot 4.7.2 实际渲染。

### 1. 左面板宽 318px，内容只占 19%

- 面板实际边界：x=13–331（宽 318px），纵向 y=12–959（高 948px）
- 面板内像素构成：底色 **70.9%**、控件色 9.5%、强调色 **3.8%**、文字 **2.9%**
- 结论：**一个 318×948 的面板，有效内容不到五分之一**，其余是空面板底色。

### 2. 存在 223px 的死空白

逐行扫描左面板内容像素，发现两段连续空白：

| 位置 | 高度 |
|---|---|
| y=686–846 | **161px** |
| y=862–923 | **62px** |

合计 223px，占面板高度的 23.5%。这不是「留白」，是没有被利用的容器高度。

### 3. 三栏夹心，地图被两侧挤压

`_layout()`（`story_app.gd:221-241`）：

```gdscript
var w:=minf(420,maxf(320,320*ui_scale));var h:=maxf(100,map_area.size.y-24)
left_panel.position=Vector2(12,12);left_panel.size=Vector2(minf(w,map_area.size.x-24),h)
right_panel.size=Vector2(minf(w,map_area.size.x-24),h);right_panel.position=Vector2(map_area.size.x-right_panel.size.x-12,12)
```

两个面板各占 320–420px，且**同时常驻**（除非 `_narrow()` 即宽度<1650 才隐藏左面板）。1600×980 下 `_narrow()` 为真，左面板被隐藏——**这说明设计意图是「窄屏互斥」，但 1600 宽已是常见桌面尺寸，等于默认状态下就少一个面板**，用户每次都要手动开。

### 4. 按钮无图标，全靠文字

全项目 116 个 `button()` 调用，标签形如「选择」「车站」「铺轨」「线路整理」「结束操作」「图层」「保存」「存档」。除顶部 `☰ 故事`、`↶`、`↷` 外，**没有任何图标**。

对比参考产品：Mini Metro 的工具栏是纯图形符号；Linear 的侧栏每项都有图标。纯文字按钮在 44px 高度下会显得又扁又空，且需要逐字阅读才能区分。

### 5. 工具栏是横向平铺，没有分组

底部工具栏（`story_app.gd:179-184`）六个按钮平铺：

```
选择 | 车站 | 铺轨 | 线路整理 | 结束操作 | 图层
```

其中「选择」和「结束操作」绑定的是**同一个回调** `_tool.bind("select")`——两个按钮做同一件事。而「图层」与前面五个不是同类操作（前五个是工具模式切换，图层是显示开关），却排在同一行。

### 6. 顶部栏信息密度失衡

`story_app.gd:143-148`：`☰ 故事` + 年份（`custom_minimum_size.x=240`）+ 撤销/重做/保存/存档/菜单。

年份标签独占 240px 且 `SIZE_EXPAND_FILL`，把其余按钮挤到右侧。年份是**只读状态**，却占了最宽的位置。

### 7. 面板内容是一串平铺的 label

左面板内容（`story_app.gd:378-389, 467-487`）是连续的 `label()` 和 `button()` 直接堆进 VBox，**没有分组容器、没有分隔、没有卡片**。20px 标题 + 16px 正文 + 15px 辅助 + 按钮，全部等间距 8px 排列——这正是 Interface Design 说的「所有东西一样重」。

---

## 根因

不是配色问题（配色对比度全部达标），是**结构问题**：

1. **面板宽度与内容量不匹配** —— 318px 宽的面板装不满，空着 80%
2. **没有信息分组** —— 平铺堆叠，缺少视觉容器和分隔
3. **交互控件缺少图形语言** —— 116 个纯文字按钮
4. **常驻双栏挤压地图** —— 地图是主画布，却让位给两个半空面板

---

## 本轮修复（已实施）

只做结构，不改配色与文案。

### 1. 面板高度随内容收缩

`_layout()` 原先固定 `h = map_area.size.y - 24`，短内容章节也撑满整屏。现在：

```gdscript
var left_h:=h
if is_instance_valid(left):
    left_h=minf(h,maxf(120,left.get_combined_minimum_size().y+24))
```

**实测效果**：面板高度 948px → 约 690px，**让出约 258px 给地图**。面板内底色占比 70.9% → 66.6%。

### 2. 左面板内容分组

新增 `section(parent, tight)` 与 `section_rule(parent)` 两个辅助函数：`tight` 用 6px 间距把标题绑到正文，`loose` 用 16px 分隔不相关区块，`section_rule` 插入分隔线。

决策卡片（`_decision_card`）从 6 个平铺 label 改为「提问区 / 选项区 / 说明区」三段结构。全项目已有 6 处调用。

### 3. 工具栏分组

底部工具栏从 6 个按钮平铺改为「工具模式组 ┃ 图层」：

```gdscript
var tool_bar:=HBoxContainer.new();center.add_child(tool_bar)
var tools:=HFlowContainer.new();tool_bar.add_child(tools)   # 选择/车站/铺轨/线路整理/结束操作
tool_bar.add_child(VSeparator.new())                        # 分组分隔
tool_bar.add_child(button("图层",_layers))                   # 显示开关，独立
```

图层是显示开关、前五个是模式切换，原先混排会让人误以为同类。

### 4. 顶部栏重排

年份标签去掉 `custom_minimum_size.x=240`，只保留 `SIZE_EXPAND_FILL`。年份是只读状态，不应独占最宽位置。

### 验证

- 解析检查：0 错误
- 渲染：4 张截图重新生成，面板收缩与分组均生效

## 未做，以及为什么

| 项 | 原因 |
|---|---|
| 图标绘制 | 需要美术资源，不是代码能解决的 |
| 配色调整 | 对比度实测全部达标，不是问题所在 |
| 文案改写 | 属 UX writing 范畴，另有一套工作流 |
| 「选择」与「结束操作」合并 | 两者绑定同一回调，但**语义不同**（空闲态 vs 结束当前操作），合并会丢失状态提示，需产品决策 |
| 真正的视觉审美判断 | **当前模型看不到图**，需要图像模型 |
