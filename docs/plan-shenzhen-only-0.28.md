## 四、P0 · 只发布深圳（已完成）

**做法：不物理删除数据。**

- `scripts/world_data.gd` 新增 `PUBLISHED_CITY_IDS := ["shenzhen"]`
- `cities()` 只返回发布城市；新增 `all_cities()` 返回全量；`city()` 改用 `all_cities()`，旧存档仍可解析
- 9 个测试文件改用 `all_cities()`，五城数据完整性校验照常运行
- 开局界面：单城时不显示"选择一座城市"，直接显示"深圳"；主菜单副标题随发布城市数变化
- 新增 `tests/published_cities_checks.gd`（18 项）

**为什么不全删：** 数据删掉后，`test_network_baselines`、`campaign_replay_all_cities`、`report_project_chapters` 等校验会崩；保留数据还能继续证明"没被改坏"，以后想加回其他城零成本。

## 五、P1 · 史料节点改决策卡（已完成）

**内容来源：** 官方页面 [“十年磨一剑”：从无到有的深圳地铁](https://www.sz.gov.cn/szstory/202212/content/post_10343762.html) 原文，核验日期 2026-11-08。三个决策点：

1. **1998-05 一期规模**：14.825 双线公里、14 站（1 号线罗湖—香蜜湖 10.682 km，4 号线皇岗—水晶岛 4.143 km），工期 4 年半
2. **2000-05 西延**：为"节省建设投资成本，提高地铁运营效益"，同意延至会展中心，增设车公庙、竹子林、会展中心 3 站（会展中心站后改名侨城东）
3. **2002-05 再延**：国家计委同意自侨城东西延至世界之窗，增设 2 站

**实现：**

- `data/decisions.json`：每张卡含 prompt、options、actual、reveal、sources（url + checkedAt）
- `scripts/decision_system.gd`：加载、校验（无来源不显示）、记录、统计
- `scripts/story_app.gd`：史料节点 intro 阶段显示卡片；未作答显示选项，已作答显示"你的选择 / 历史实际 / 原因 / 来源"
- 选择写入 `challenges.json` 的 `decisions` 键，**不进世界存档**，旧 `challenges.json` 用 `.get` 容忍缺键
- 新增 `tests/decision_checks.gd`（26 项，含"世界存档字节不变"断言）

**明确边界：** 选项里的非历史分支只用于对照，不宣称发生过；卡片不改变本章建设与历史判定。

## 六、P2 · 规划章改提案制（待做）

12 个必做规划章现在是"按官方站序施工"。改成：

1. 给目标（覆盖哪些片区、端点时间、与既有线路的换乘要求）
2. 玩家自己画线
3. 系统按官方方案对比评分（覆盖命中、换乘命中、长度效率），官方方案作为"参考答案"展示

**数据：** 新增 `data/proposals.json`，每章含 brief、targets、official（引用 futurePlans 的 stationIds）。

**评分：** 纯几何，不涉及客流（项目明确不做客流经营）。结果写 `challenges.json` 的 `proposal` 键。

**试点：** 先做 3 章（17、19、29 号线），验证机制后再铺开。

**测试：** `tests/proposal_checks.gd`——评分边界、不写世界存档、旧 challenges.json 可读。
